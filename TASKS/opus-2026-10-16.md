## 1. The portfolio hides most of what the user owns (highest impact)

Measured on `0x26a1a7c87f72fe37ca57ab92f24353ff12b1110a`: `alchemy_getTokenBalances` returns **47 non-zero
ERC-20 balances**; only **3** of those addresses exist in our own `tokens` table, and `PortfolioService._compute`
keeps only the known ones:

```python
pairs = [(by_addr[a], raw) for a, raw in held.items() if a in by_addr]
```

So 44 real holdings are invisible. The owner: *"there are many coins worth practically nothing, why can't I see them"*.

Required:

- Every non-zero balance the chain reports gets a row — indexed by us or not.
- For tokens we never indexed: `symbol` / `name` / `decimals` in **one batch** of `eth_calls` (never one
  request per token), and price + pool liquidity from DexScreener's batched tokens endpoint (up to 30
  addresses per request) behind a short Redis cache. Liquidity matters: it decides whether a value is real.
- A token with no market data still appears — symbol if known, value `—`/0. Never a made-up number, never a
  silent drop.
- Wrap those lookups so one odd token cannot fail the whole page.
- A portfolio load stays well under ~2 s warm and must not sweep one `balanceOf` per known token (2 900 of
  them) — that is what made `/portfolio` a 502 earlier today.

## 2. The struck-through row must go

Commit `fcd2b91` shows a holding worth more than its pool can pay out, in the list, with a struck-through
value and "can't be sold at this size". The owner rejects that row outright.

Required: exclude such holdings from `holdings` entirely; expose only a **count** so the screen can state,
without printing the fantasy number, that N tokens were left out. The total must still never include
uncollectable value — that rule is correct and stays.

Repro that must not regress: a wallet holding 66 units of a token calling itself "ETH"
(`0x02865c612393ceb2482fdc08fb30fce113305d12`, pool $2 055) reports **$161 609** today; we already rate that
token RISKY with "top holder sells: -100%".

## 3. A pasted contract leaves the user staring at skeletons for ~70 s

Reproduced with the phone's exact request:

```
curl -s -w "%{http_code} %{time_total}" localhost:8000/safety/0x0107ad33b6e2b4b84bbb4487151fb39b8ae7acf2
-> HTTP 200 in 69.6 s      (a correct DANGER verdict, 69 seconds late; the API logs "slow_or_failed_request")
```

Cause: `SafetyService.get()` runs the full scan **inline inside the HTTP request** when nothing is cached
(`safety_service.py:131`). No queue, no 202, no progress — `Safety.tsx` shows `<Skeleton rows={3}/>` for the
whole duration. This is the path for **every** address the user pastes that we have not indexed.

Required: a request must never hold a socket for a scan. Return immediately (202 + a handle the client can
poll) or stream progress. The screen must show what is happening ("checking holders…", elapsed time) and
always offer a way out. A user-pasted token goes to the **priority** queue and must never queue behind bulk
work. Never show a verdict before it exists; UNKNOWN stays a possible, honest answer.

## 4. "Paste address" does not work on a phone, and the field has no submit

`Safety.tsx:65-69`: the empty-state CTA reads `navigator.clipboard.readText()`. The expression

```js
(await navigator.clipboard?.readText().catch(() => ''))?.trim() ?? ''
```

short-circuits to `undefined` when the Clipboard API is missing, then reports *"No token address in your
clipboard"* — a silent failure. On iOS the read needs focus/permission anyway. And `AddressBar`
(`Safety.tsx:74-82`) submits **only** on Enter, so a manually pasted address has no button to press.
Owner: *"the paste button doesn't work, I have to enter it by hand"*.

Required: an explicit visible submit ("Check") beside the input that works with a typed or pasted address; a
paste affordance that cannot fail silently (if the clipboard read is refused, say so and focus the input
rather than pretending the clipboard was empty); keep Enter working; keep the lowercase normalisation and
the `isAddress` guard.

## 6. Swap inside the app, confirmed in the wallet, not on another site

Today Buy/Sell deep-link to `app.uniswap.org` (`VITE_SWAP_URL`). The owner wants the confirmation in-app: we
build the transaction, the user's own wallet shows its confirm dialog immediately, no redirect.

Verified in Uniswap's own chain metadata for Robinhood Chain (4663): `supportedURVersions`
[UniversalRouter 2.0, 2.1.1], `supportsV4: true`, `backendSupported: true`; WETH
`0x0Bd7D308f8E1639FAb988df18A8011f41EAcAD73` matches ours; USDG
`0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`.

**Decision taken: it must work without any API key.** Quotes come through a server-side proxy:
if a Uniswap Trading API key is configured (`SWAP_API_KEY`, empty by default) use it — it routes
v3/v4/UniswapX; without one, quote on-chain via v3 `QuoterV2` plus the v4 `Quoter`, and when no route is
found **say so** instead of inventing a number. The key must never reach the browser.

Flow: amount → live quote → the token's **safety verdict shown in the same sheet** (this is the product:
nobody buys a DANGER token without seeing it) → one-time Permit2 approve when needed → send via
`eth_sendTransaction` on the connected provider → track the receipt → refresh the portfolio.

Show min received, slippage (with a sane cap), price impact, fee. Handle wallet rejection (code 4001)
quietly, without re-prompting. Keep the external deep link as a fallback for wallets that cannot send.
Read the router and Permit2 addresses from configuration and **verify them against the chain** before the
first real swap. Tests for the quote/slippage math.

## 7. The visual system — modern, high quality

The whole look is one 118-line `styles.css`: Manrope, surfaces `#0B0E11`/`#141920`, accent `#00C805`, a 1px
border on every card, radii 14-20px, no elevation, no spacing scale. It reads flat and dated.

Required: a real token system (surface levels, hairline separators instead of a border on every card, radius
scale 8/12/16/24/99, elevation via soft shadows); a type scale with clear hierarchy (display / title / body /
caption with real line-heights and tracking); **one** bottom-sheet component reused for every confirmation,
including the swap. Honest states everywhere: shimmer skeletons, empty, error, and progress **with text**
(never a silent skeleton — see item 3). Transitions 150-200 ms ease-out with `prefers-reduced-motion`
respected. Focus rings, hit areas ≥ 44 px, muted-text contrast ≥ 4.5:1. Keep `Chainfolio.dc.html` in sync or
state which file is the source of truth. No framework change; keep the phone-centred layout and four tabs.
